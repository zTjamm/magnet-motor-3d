# AGENTS.md

## Что это

Одностраничная 3D-визуализация «вечного двигателя на магнитах»: Three.js + 2D-canvas
поверх одного `index.html`. Сборки нет, единственная зависимость — `three@0.169.0`
с CDN (через importmap). Вся физика, сцена и UI лежат в `index.html`.

## Запуск и проверка

- Рекомендуется локальный сервер: `python -m http.server 8000` в корне, затем
  `http://localhost:8000`. Прямое открытие `file://` может упереться в CORS
  ES-модулей — на этот случай в странице есть сообщение-заглушка `#fallback`.
- Нужен интернет: Three.js грузится с `cdn.jsdelivr.net`.
- Сборки, тестов, линтера и `package.json` нет — не ищи `npm test` / `npm run build`.
- Проверка вручную: открыть страницу и консоль. Признак успеха — `window.__threeLoaded === true`
  и отсутствие ошибок; иначе показывается `#fallback`.

## Физика — не заменять на «вечную»

- Магнитные диполи: `B = k(3(m·r̂)r̂ − m)/r³`, потенциал `U = −Σ m·B`.
- Крутящий момент ротора считается как `τ = −dU/dθ` (центральная разность,
  `TORQUE_STEP`), а не как `m × B`. Для движущегося диполя в неоднородном поле это
  разные величины, и вариант `m × B` численно разгоняет систему.
- Интегратор — скорость-Верле, фиксированный шаг `1/480` с, накопитель в `animate()`.
  Не заменять на явный Эйлер без проверки дрейфа энергии.
- Трение вязкое. «Остановка» — численная статическая: латчится через `settleTimer`
  при малой ω и малом |τ|; при трении 0 не срабатывает, энергия сохраняется.
- Единицы условные (у.е.), не СИ. Не приписывать реальные Н·м и ватты.

## Устройство `index.html`

- `params` / `state` — единственный источник состояния; обработчики слайдеров пишут в `params`.
- `physicsStep(dt)` — только физика; `animate()` — аккумулятор шага и рендер.
- `rotorGroup.rotation.y = -state.theta` — соглашение между физическим углом в
  плоскости XZ и поворотом Three.js. Не путать знак.
- Стрелки сил (`forceOnMagnet`) иллюстративные: на динамику не влияют.
- График рисуется в отдельном 2D-canvas из `history` (последние ~900 сэмплов).
- `window.__sim = { state, params, magneticTorque, potentialEnergy }` — отладочный
  хук для консоли и автоматических проверок.
- Весь текст интерфейса русский; сохранять язык.

## Подводные камни

- При изменении силы магнитов или угла статора вызывается `wakeRotor()`: иначе
  ротор останется «залипшим» в старом положении равновесия.
- Не уменьшать `SOFT_MIN_R` без проверки: сила ~`1/r⁴`, возможны численные выбросы.
- Проект намеренно показывает, что вечного движения нет. Не добавлять режим, в
  котором ротор разгоняется «от магнитов».
